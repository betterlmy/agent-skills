# 前向评估用例

这些用例用于验证触发边界、扫描深度和报告证据，不代替脚本测试。

## 应触发：常规整仓体检

提示：`请对这个 Go 服务仓库做一次完整代码质量体检，重点看架构、错误处理、并发和测试债务。`

期望：使用 `standard`；先读取仓库指令与 Makefile，再运行获准的基线命令；人工结论必须有源码证据；输出按优先级整理的画像报告。

## 应触发：接手前深度审计

提示：`团队下周要接手这个 Go 单体仓库，请做深度健康度审计，并说明鉴权和支付模块的调用影响面。`

期望：使用 `deep`；完整检查依赖方向、调用入口、高风险域和受影响测试；区分语义索引证据、文本候选与人工判断。

## 边界场景：离线快速摸底

提示：`当前环境不能联网，只想快速确认这个 Go 仓库能否编译、是否有明显 lint 问题。`

期望：使用 `quick`；默认保持离线和模块只读；缺失工具标为未运行；不得自行安装工具或启用网络。

## 应触发：单个 package

提示：`只审计 internal/auth 这个 package，不要评价整个仓库。`

期望：使用 `package` + `standard`；工具扩展到 package，报告明确不得外推为仓库级结论。

## 应触发：工作区 Diff

提示：`审查当前未提交的 Go 改动，重点关注并发安全和错误处理。`

期望：使用 `diff working`；覆盖未暂存、已暂存和未跟踪 Go 文件；读取 patch、所属 package 和相关测试；区分新增问题与既有上下文问题。

## 应触发：Revision range

提示：`审计 origin/main...HEAD 之间的 Go 变更及受影响测试。`

期望：使用 `diff-range` + `standard`；不自行 fetch；revision 不存在时报告预检失败。

## 不应触发：非 Go 项目

提示：`审计这个纯 Python 仓库的整体代码质量。`

期望：不触发本 Skill，因为目标不是 Go 代码。
