# 前向评估用例

这些用例用于验证触发边界、扫描深度和报告证据，不代替脚本测试。

## 应触发：常规整仓体检

提示：`请对这个 Go 服务仓库做一次完整代码质量体检，重点看架构、错误处理、并发和测试债务。`

期望：使用 `standard`；先读取仓库指令与 Makefile，再运行获准的基线命令；人工结论必须有源码证据；摘要使用类型与严重度矩阵，正文先按问题类型分类、类型内部再分级。

## 应触发：接手前深度审计

提示：`团队下周要接手这个 Go 单体仓库，请做深度健康度审计，并说明鉴权和支付模块的调用影响面。`

期望：使用 `deep`；完整检查依赖方向、调用入口、高风险域和受影响测试；区分语义索引证据、文本候选与人工判断。

## 边界场景：离线快速摸底

提示：`当前环境不能联网，只想快速确认这个 Go 仓库能否编译、是否有明显 lint 问题。`

期望：使用 `quick`；默认保持离线和模块只读；缺失工具标为未运行；不得自行安装工具或启用网络。

## 应触发：单个 package

提示：`只审计 internal/auth 这个 package，不要评价整个仓库。`

期望：使用 `package` + `standard`；工具扩展到 package，报告明确不得外推为仓库级结论。

## 应触发：工作区 Diff

提示：`审查当前未提交的 Go 改动，重点关注并发安全和错误处理。`

期望：使用 `diff working`；覆盖未暂存、已暂存和未跟踪 Go 文件；读取 patch、所属 package 和相关测试；区分新增问题与既有上下文问题。

## 应触发：Revision range

提示：`审计 origin/main...HEAD 之间的 Go 变更及受影响测试。`

期望：使用 `diff-range` + `standard`；不自行 fetch；revision 不存在时报告预检失败。

## 输出结构：多类型多级问题

提示：`审计结果同时发现一个阻断级 SQL 注入、一个应修复的 goroutine 泄漏和两个错误处理问题，请整理报告。`

期望：先分别进入“安全与敏感信息”“并发与资源安全”“错误处理与健壮性”类型，再在各类型内部按阻断级、应修复、可优化分级；不得先建立一个跨类型的“阻断级问题”总清单。摘要用“问题类型 × 严重度”矩阵，最终修复优先级允许跨类型排序。

## 输出边界：未审计不等于零问题

提示：`只审计 internal/auth 的鉴权和错误处理，不检查数据库与并发。`

期望：已检查且无问题的类型记为 `0` 或“无已确认问题”；持久化、并发类型写“未审计”或“不适用”并说明原因，不能填 `0`。

## 工具边界：离线依赖不完整

提示：`离线审计这个 Go 仓库，模块缓存不完整，请不要把环境失败算成代码问题。`

期望：package 解析只报告一个共同前置失败，真实 package 数量写“未知”；依赖 package 语义的工具级联标为未运行，不重复输出同一模块错误。

## 工具边界：冲突的继承环境

提示：`当前环境设置了 GOFLAGS=-mod=mod，但审计不得修改 go.mod/go.sum。`

期望：过滤继承的模块模式并强制 `-mod=readonly` 或适用的 vendor 模式；输出最终生效 GOFLAGS，不使用 `eval` 解析环境值。

## 显式动态验证

提示：`仓库没有测试 Makefile，请只对 internal/auth package 运行 test、race 和 coverage，超时 30 秒。`

期望：获得明确授权后只对所属 package 使用 `--test --race --cover --test-timeout 30s`；不得扩大到整仓，也不得默认联网。

## 不应触发：非 Go 项目

提示：`审计这个纯 Python 仓库的整体代码质量。`

期望：不触发本 Skill，因为目标不是 Go 代码。
