# 报告格式（收口）

报告必须回答“审计了什么、发现什么、证据覆盖到哪里、最该先修什么”。局部结果不得包装成整仓健康画像。

## 报告结构

### 1. 范围与结论摘要

- 摘要面向决策者，先用一句话说明本次范围能否接受，再列阻断项、最先处理的三项和最重要的未验证边界；详细证据留在正文。
- 范围类型、用户指定路径或 revision、扫描深度、日期和 Go 版本。
- 正式审计范围、为理解行为读取的上下文范围、工具实际扩展的 package 范围。
- 未审计区域、未运行工具和不可外推的结论。
- 使用“问题类型 × 严重度”矩阵统计正式发现；系统性技术债单独计数，不混入严重度小计。

| 问题类型 | 阻断级 | 应修复 | 可优化 | 小计 |
| --- | ---: | ---: | ---: | ---: |
| 安全与敏感信息 |  |  |  |  |
| 并发与资源安全 |  |  |  |  |
| 持久化与数据 |  |  |  |  |
| 错误处理与健壮性 |  |  |  |  |
| 复杂度与可读性 |  |  |  |  |
| 可测试性与可维护性 |  |  |  |  |
| 契约与兼容 |  |  |  |  |
| 合计 |  |  |  |  |

矩阵中的 `0` 只表示该类型已经审计且没有确认问题；未检查写“未审计”，与当前范围无关写“不适用”，两者都不能记为 `0`。`quick` 未做语义审计时可以省略矩阵，但必须明确说明“未执行分类问题审计”。

`repo`/`module` 可以给出相应层级的整体健康度；其他范围使用“本次范围内”表述。

### 2. Diff 摘要（仅 diff 范围）

- Diff 来源：working、staged 或 revision range。
- 新增、修改、重命名、删除的 Go 文件及所属 package。
- 变更意图与关键行为变化；无法从证据确认时明确标注未知。
- 本次变更新增的问题、被变更放大的既有问题、只作为上下文观察到的问题分别列示。
- 删除文件无法由脚本检查当前内容时，说明依据来自 patch 和剩余调用方。

### 3. 系统性问题

只在已审计范围内聚类跨文件重复模式。例如：

- “范围内 8 处忽略关键返回错误，其中 3 处位于写入路径”。
- “4 处请求链路使用 `context.Background()` 绕过取消”。
- “同一 package 同时承担编排、持久化和协议转换，相关测试难以隔离”。

每条注明主要问题类型、关联类型、模式、出现次数、代表性 ` 文件名:行号 `、适用范围和建议方向。优先引用正式问题编号，不重复复制完整证据和修复建议。系统性技术债不替代各具体问题的严重度。不能把局部计数写成“全仓”。

### 4. 结构与影响面

- `repo`/`module`：分层依赖、god package 候选、全局状态和工程配置。
- package/目录/hotspot：所属层次、直接依赖、调用方和公开契约。
- files/diff：所属函数与 package、行为变化、受影响调用方和相关测试。

### 5. 分类问题清单

正式问题必须先按问题类型分类，类型内部再按严重度分级，禁止先汇总全部阻断级、再汇总全部应修复。固定层级为：

1. 安全与敏感信息
2. 并发与资源安全
3. 持久化与数据
4. 错误处理与健壮性
5. 复杂度与可读性
6. 可测试性与可维护性
7. 契约与兼容

每个类型内部使用以下结构：

```markdown
### 5.x 问题类型

#### 阻断级

##### 问题标题

- 编号：类型缩写-严重度-三位序号，例如 `SEC-B-001`
- 位置：` 文件名:行号 `
- 范围归属：
- 问题描述：
- 证据与确认状态：工具复现 / 运行或测试复现 / 源码确认 / 调用可达性确认 / 仓库外可达性未知 / 有依据的推断
- 影响：
- 建议：

#### 应修复

...

#### 可优化

...
```

同一类型、同一严重度内，依次按影响面、发生可能性和证据强度排序。没有确认问题写“无已确认问题”；没有检查写“未审计：原因”；与范围无关写“不适用：依据”。空分级可以省略，但类型的审计状态不能含糊省略。

证据可以增量记录到草稿，但正式报告只能在候选回读、去重、分类和定级后整体收口。严重度矩阵必须从最终问题集合计算，不得把 append-only 草稿直接当作最终报告。

### 6. 修复优先级

按风险、影响面和修复成本排序：

- 立即修复：已确认的阻断级问题，且修复路径明确。
- 计划修复：应修复问题，或需要迁移方案的阻断级问题。
- 持续改善：可优化项与系统性技术债。

## 严重度与证据要求

- 每个代码结论指向 ` 文件名:行号 `；diff 结论说明对应变更及当前上下文。
- 区分工具检出、运行或测试复现、源码确认、语义或 patch 证据、调用可达性与人工推断，并注明未验证边界。
- 工具未运行时标注“未运行/未安装”，不得用“通过”占位。
- 推断性结论明确标注为推断。

## 禁止

- 不输出无优先级的问题流水。
- 不把静态检查通过表述为业务行为已验证。
- 不编造工具未运行的结果。
- 不对未读代码下结论。
- 不输出真实凭证、个人信息或未脱敏请求内容。
- 不把上下文中既有问题伪装成本次 diff 引入。
- 不把 package、目录、文件或 diff 结果外推为仓库整体结论。
- 不按严重度跨问题类型平铺正式发现。
