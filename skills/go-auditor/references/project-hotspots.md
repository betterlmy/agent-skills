# 项目高风险域（横切）

高风险域是改动牵动面大、失败代价高的业务范围。本文件定义其来源、上下文扩展和通用兜底；`hotspot` 可以作为正式审计范围，也可以是其他范围中的优先上下文。

## 注入接口：由项目声明高风险域

优先读取项目根的 `AGENTS.md` / `CLAUDE.md` / 交接文档，提取已声明的高风险域。常见声明形式：

- "高风险区域""high-risk""影响上游调用方"等关键词段落。
- 列出的敏感模块（鉴权、token、注册、租户成员、验证码、对象存储、支付、计费等）。
- 列出的上游/下游消费方（改动需回归测试的范围）。

提取后，对这些区域：

1. 单独走查第二步全部 reference（健壮性/并发/持久化/安全），不抽样。
2. 从入口注册、接口实现、包导入关系和相关测试四个方向评估影响面；优先使用宿主提供的语义索引或代码图工具，文本搜索只用于发现候选。
3. 在报告里单列"高风险域走查"章节，标注牵动面。

## 通用兜底：项目未声明时

未声明时，按以下通用高敏区推断并**明确标注为推断**（不是项目事实）：

- 鉴权与身份：登录、token 签发与校验、密码、MFA、会话、RBAC/ABAC。
- 凭证与密钥：密钥生成、签名、加密、access key/secret 管理。
- 多租户隔离：租户边界、越权、容量控制、成员管理。
- 资金与计费：支付、订单、额度、对账。
- 并发与资源：分布式锁、限流、队列、连接池。
- 外部 IO：对象存储、第三方 API、消息队列、 webhook。
- 数据迁移与 Schema：DDL 变更、数据回填、兼容性。

兜底推断要提示用户：建议在项目 `AGENTS.md` 显式声明高风险域，以提升后续扫描精度。

## 上游/下游影响评估

高风险域改动的影响面要评估：

- 用 `go list -f '{{.ImportPath}} {{join .Imports " "}}' ./...` 检查包级依赖方；语义工具可用时用其确认接口实现、调用方和影响范围，不可用时用 `rg` 定位候选，再结合源码及相邻、上层包测试确定回归范围。
- 对照 `AGENTS.md`/`CLAUDE.md` 中列出的消费方仓库（如网关、设备服务）。
- 在报告里给出"牵动面"说明，提醒需更广回归测试。

## 与通用扫描的关系

- `repo` 审计可以先做全仓基线再放大高风险域；局部、文件和 diff 审计只走查与用户目标相交的高风险域，不自动扩大正式范围。
- 两者结论都要落到 ` 文件名:行号 `。高风险域提高审查优先级，但严重度仍由可利用性、正确性影响、影响面和现有控制措施决定，不机械上调。

## 产出

- 项目声明的高风险域清单（或"未声明，按通用高敏区推断"说明）。
- 每个高风险域的走查结论与牵动面。
- 上游/下游受影响范围。
