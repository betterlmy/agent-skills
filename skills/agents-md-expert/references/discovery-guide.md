# 仓库调查指南

## 目标

调查的目的不是理解整个项目，而是找出会影响编码 Agent 行为的事实。优先读取受版本控制的权威文件，并让每条生成规则都能追溯到来源。

## 1. 确认作用域

1. 确定仓库根目录；若不是 Git 仓库，明确目标目录边界。
2. 定位目标文件，并查找宿主规则所定义的上级、同级和下级指令文件。
3. 确认目标是仓库根规则还是子项目差异规则。
4. 记录初始工作区状态，只用于比较，不重置已有改动。

不要默认所有宿主都以相同方式继承 `AGENTS.md`。宿主语义不明确且影响内容时，询问用户。

## 2. 证据来源

| 要确认的事实 | 优先证据 |
| --- | --- |
| 技术栈与版本 | 依赖清单、锁文件、工具链配置、容器镜像、CI |
| 构建和运行命令 | Makefile、Taskfile、package scripts、构建配置、CI |
| 测试与静态检查 | CI jobs、测试配置、脚本、贡献指南 |
| 目录职责 | 目录内文档、构建入口、模块清单、源码结构 |
| 生成文件 | 生成器配置、文件头、构建任务、版本控制规则 |
| 数据库迁移 | 迁移工具配置、脚本、部署流程文档 |
| API 兼容性 | API 规范、版本策略、契约测试、贡献规范 |
| 提交和发布 | 贡献指南、提交检查配置、发布脚本 |

README 可以作为入口，但涉及命令、版本和约束时应与机器可读配置交叉确认。

## 3. 最小上下文原则

- 先列文件和识别项目类型，再读取最相关文件。
- 优先使用版本控制文件列表，避免遍历依赖目录、构建产物和缓存。
- 不读取 `.env`、密钥、云凭据、SSH 配置或生产数据。
- 不因发现更多文档就全部加载；沿与当前规则直接相关的引用继续读取。
- Monorepo 先理解根规则，再调查目标子项目，不把其他包的命令误写为全局命令。

## 4. 事实记录

起草前，在工作上下文中记录：

| 字段 | 含义 |
| --- | --- |
| 候选规则 | 可能写入 `AGENTS.md` 的指令 |
| 来源 | 仓库文件、现有指令或用户确认 |
| 作用域 | 根目录、子项目或特定文件类型 |
| 置信度 | 已确认、存在冲突、未知 |
| 验证方式 | 静态核对或可运行命令 |

存在冲突时优先采用更权威、作用域更准确的来源；无法判断时不要自行选择。

## 5. 命令安全分类

### 可自动运行

同时满足以下条件时可自动运行：

- 命令由仓库配置明确声明；
- 不需要安装或升级依赖；
- 不访问发布环境或持久业务数据；
- 不修改 Git 历史或受版本控制文件；
- 预计运行时间和资源消耗合理。

典型候选包括只读格式检查、静态分析和隔离的单元测试，但仍需结合项目脚本确认实际副作用。

### 必须先询问

- 安装依赖、代码生成、自动修复格式；
- 数据库迁移、集成测试或依赖外部服务的测试；
- 容器编排、基础设施变更、发布和部署；
- 脚本内容不透明或可能写入仓库；
- 预计耗时、费用或资源消耗明显。

### 禁止自行执行

- 推送代码、强制更新 Git 历史；
- 删除或清理用户文件；
- 使用生产凭据或修改生产数据；
- 通过跳过、删除或弱化测试规避失败。

## 6. 调查完成条件

满足以下条件即可停止调查：

- 已确定目标作用域和适用上级规则；
- 每个拟写命令都有来源和适用目录；
- 已识别生成文件、高风险操作和最低验证要求；
- 剩余未知事项不会影响结果，或已向用户提问。
