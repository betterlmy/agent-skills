# AGENTS.md 审查量表

## 严重级别

- **High**：可能导致破坏性操作、泄密、错误修改作用域、跳过关键验证，或使用明显无效的命令。
- **Medium**：可能造成重复劳动、错误假设、维护困难、过度阻塞，或遗漏重要边界。
- **Low**：不阻塞正确执行，但影响清晰度、简洁性或一致性。

## 检查项

### 真实性

- 技术栈、目录、版本和命令能否从当前仓库确认？
- 是否把建议、猜测或历史状态写成强制事实？
- README 与机器可读配置冲突时，是否核实权威来源？

### 作用域与优先级

- 文件是否位于正确目录并明确适用范围？
- 是否重复上级规则，或错误声称覆盖更高优先级指令？
- 子项目命令是否被误写成全仓库命令？

### 可执行性

- 规则是否使用可判定措辞？
- 命令是否精确，并说明执行目录与前置条件？
- 验收标准是否区分已运行、可运行和未验证？
- 是否要求项目结构、技术栈、命令或开发约束变化时同步更新适用作用域的 `AGENTS.md`？
- 仓库事实已经变化时，现有规则是否仍引用旧目录、旧技术栈或失效命令？

### 最低结构与长度

- 是否分别包含“仓库定位”“技术栈”“目录结构”“文档索引”和“Skill 索引”五个章节，或使用了清晰的等价中英文标题？
- 文件是否不超过 240 行？超过上限应作为未完成项处理，而不是仅作风格建议。

### 安全性

- 是否包含密钥、凭据、生产数据或用户私有绝对路径？
- 是否允许推送、强制更新历史、删除文件、发布或迁移而无需确认？
- 是否可能通过删除、跳过或弱化测试掩盖失败？
- 是否保护用户已有改动？

### 内容质量

- 是否包含不改变 Agent 行为的项目介绍？
- 是否存在“保持高质量”“遵循最佳实践”等空泛规则？
- 是否机械套用与项目无关的章节？
- 是否遗漏生成文件、迁移、公开 API、依赖、兼容性边界或防漂移规则？
- 文档长度是否与项目复杂度相称？

## 输出格式

先按严重级别排序问题，每项使用：

```text
High: 问题标题
位置: AGENTS.md:行号
影响: 可能造成的实际后果
依据: 对应仓库事实或适用规则
建议: 最小且可执行的修复方式
```

随后报告：

- 待确认问题或假设；
- 已执行的静态审计和项目验证；
- 若发生修改，概括删除、补充和修正的规则。

如果没有发现问题，应明确说明已检查范围和仍未验证的事项，不要宣称文件绝对正确。

## 对象类型与上下文预算

五章节规则用于仓库入口；用户全局规则不填项目结构，插件模板与参考手册按实际用途检查。使用 audit_agents_md.py 的 --scope 明确对象；所有模式保留秘密与危险命令检查。生效指令同时核对字节量、优先级、授权延续、失效引用与重复规则，不用长行满足行数限制。
