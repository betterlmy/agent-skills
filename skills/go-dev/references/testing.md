# Go 测试与验证

## 选择验证入口

- 优先运行仓库声明的 Makefile、Taskfile、脚本或 CI 等价命令，不虚构 `lint`、生成器或集成环境。
- 最小基础通常包括 `gofmt`、相关包测试和 `go vet`；是否运行全量测试、`-race`、集成测试和生成检查取决于范围与环境。
- 先跑最接近改动的快速测试，再跑受影响范围和仓库要求的完整检查。

## 测试边界

- 测试公开行为、状态转换、错误分类和副作用，不锁死无关实现细节。
- 修改错误处理时覆盖成功、已知错误、未知错误、取消和 Deadline。
- 修改 HTTP/gRPC 时覆盖协议矩阵、认证来源、输入边界、空集合、大小限制和异常恢复。
- 修改数据库时覆盖事务提交/回滚、未找到、约束冲突、Rows 错误和并发语义。
- 修改 goroutine、Channel、锁或缓存时运行适合的竞态测试，并覆盖退出、取消和容量上限。
- Fake 应实现行为边界，不复制生产实现；时间、随机数、外部 API 和重试优先通过窄接口注入。

## 常用命令

只有仓库适用且命令存在时才运行：

```bash
gofmt -w <changed-go-files>
go test ./path/to/affected/...
go test ./...
go test -race ./path/to/concurrent/package
go vet ./...
go mod verify
```

- 不擅自执行会下载依赖、启动容器、连接数据库、访问网络或修改外部状态的命令。
- 需要真实数据库、Docker、云服务、付费 API 或生产凭据时，先说明副作用并取得批准。
- 不把因环境缺失而跳过的测试报告为通过。

## 生成物与差异

- 修改 `.proto`、OpenAPI、sqlc 查询、Mock 输入或其他生成源后运行仓库固定生成器并检查漂移。
- 不手工修补生成文件来绕过生成失败。
- 完成前运行差异检查，确认没有调试日志、临时文件、凭据、无关格式化和意外依赖升级。
- 最终汇报区分实际修改、通过的检查、跳过项、未运行的环境验收和剩余风险。
