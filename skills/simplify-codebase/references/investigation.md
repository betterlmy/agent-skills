# 调查手册

目的：产出有边界的覆盖地图；范围内每个领域都已检查或被明确排除，然后只对有契约证据支持的候选项排序。

## 建立覆盖地图

从最大或最核心的生产表面开始，按职责而不是按文件类型划分系统。常见领域包括：入口、编排和运行时控制；公开 API、命令、配置和特性选择；领域状态、缓存、事件和生命周期转换；持久化、schema、迁移、回放和兼容性；协议、插件、依赖注入、反射和代码生成；前台和后台执行、worker、进程与资源所有权；包、适配器、示例、脚本、测试、快照和文档。

按仓库调整这些领域。对每个领域写明已检查的入口、读过的核心生产路径、执行的搜索、查阅的历史或决策记录，以及未解决的盲区。只有每个范围内领域都被检查，或带理由明确排除，覆盖才算完成。

在用户已授权且范围足够广时，可以并行调查，但每个工作者必须负责不重叠领域、输出相同证明记录；应按置信度和所有权边界汇总，而非按到达顺序或发现数量。

## 寻找维护负担

用这些视角生成线索：

- **休眠契约**：导出、hook、事件、选项、包、协议字段或命令没有当前生产消费者。
- **分裂事实**：多个状态、摘要、缓存、格式或事件族编码同一事实，必须持续同步。
- **无主灵活性**：抽象、兜底、策略、标志或扩展点承诺的可能性没有当前产品路径拥有。
- **转发层**：包装器、包、服务或路由只转发行为，既没有降低耦合也没有建立边界。
- **并行状态机**：标志、promise、队列、哨兵、控制器或回调描述同一转换。
- **边界表演**：校验、复制、回滚或恶意对象防御位于受信任交接处，而非真实信任或所有权边界。
- **本地基础设施**：自定义解析、重试、分帧、匹配、diff、调度或集合代码重复实现了合适的平台能力或依赖。
- **支持拖累**：测试、示例、快照、生成预期或文档是其他未使用表面唯一留下的理由。
- **功能化石**：实现已废弃或删除，但 schema、配置、测试、兼容逻辑或设计记录还保留其轮廓。

视觉相似不等于重复；独立实现可能在测试接口、隔离故障域、保护不同所有者或支持不同兼容契约。

## 沿证据阶梯上升

按最强证据分类每条线索：

1. **异味**：能看见复杂、重复或别扭。
2. **静态线索**：搜索或分析器报告没有或很少使用。
3. **消费者地图**：每个仓库命中均已分类，并读过相关调用方和被调方。
4. **契约证明**：动态加载、外部使用、持久化、兼容性、所有权和设计历史均已解决。
5. **行为证明**：决定性检查和恢复路径表明错误变更会如何暴露。

异味和静态线索不是删除授权。高置信度变更通常需要契约证明和行为证明。

## 分类消费者与历史

不要只统计命中数。把每项命中分为运行时（已发布代码、配置、迁移、加载器、部署脚本和真实入口）、支持（测试、文档、注释、快照、仅作说明的示例和生成预期）或不确定（fixture、公开导出、可能也是 smoke 路径的示例、插件注册、反射、惰性导入、字符串分发、清单、生成代码和外部包消费者）。

搜索精确符号及替代调用形式、文件和包名、配置与环境键、事件和协议字符串、序列化字段、注册标识符和文档示例；必须阅读周围控制流。可通过注册和加载代码、发布边界、范围内下游仓库、持久化数据、兼容策略与发布历史解决不确定消费者；若外部消费无法界定，应说明并降低置信度。

借助 blame、日志、PR、Issue、ADR、RFC 和注释回答：最初解决了什么失败、需求或计划；条件是否仍存在；当前由谁拥有该决策；什么新证据超过原始理由；移除后哪种能力难以恢复。旧日期或安静文件仅是发现线索，曾被拒绝的方案仍可能阻止重犯错误。

## 评估替代依赖与排序

平台或成熟依赖只有在消除的义务大于新增义务时才算简化。比较精确语义、剩余不支持行为、维护与采用成本、发布节奏、安全状况、传递依赖、平台兼容、迁移成本、包装器大小、可删除测试和供应链暴露；优先平台能力，其次已有依赖，最后才是新依赖。若包装器仍保留大部分本地策略，只委托了少量原语，就不是简化，应记录残余契约。

独立衡量可达性与契约证据置信度、影响范围与可逆性、废弃的维护概念、放弃的可观察行为或选择权、验证强度，以及实现和迁移成本。不要奖励删除行数、候选数量或戏剧性范围；没有安全候选是有效的证据结论。
