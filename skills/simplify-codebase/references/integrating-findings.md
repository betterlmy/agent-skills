# 整合发现

目的：针对目标仓库当前契约，把每条导入发现映射为保留、合并、驳回、已被替代或未解决。

## 确认独立贡献

将每个来源与自己的合并基点或权威默认分支比较，而不是只与当前工作分支比较。识别专属于来源的代码改动、证明记录、决策记录、注释和验证结果；把过期发现视为当前树上的假设。

对每个导入候选项，重新检查目标状态的符号、消费者、动态入口、历史和兼容性；保留达到当前置信门槛的非重叠证据；将重叠理由合并到拥有契约的记录；丢弃重复、较弱表述和被新代码推翻的发现；保留最强反论、取舍、验证边界和未解决不确定性；区分移植的提案与已实施并验证的改动。

只有每项来源发现都已带理由映射为保留、合并、驳回、被替代或未解决时，整合才完整。原始候选数量不是必须保留的内容。

## 安全整合变更

只应用用户授权的代码或文档。按当前所有权和行为而不是来源顺序解决重叠；在合并状态重新运行残留搜索和验证，孤立分支的结果不能证明已整合树。更新 PR 时，报告真正保留的范围、调查来源、合并与驳回项、故意排除项、当前头部验证和剩余审查缺口。候选集或验证仍在变化时保持草稿或其他未完成标记；关闭、替代、评论或以其他方式修改外部评审只能在用户授权后进行。
