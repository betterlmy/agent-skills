# 简化代码库

目标是减少代码库必须持续保持一致的概念和义务，而非单纯减少行数。审查结果可以是“当前实现有充分理由，应保留”。

## 选择模式和范围

先确定授权模式：

- **审计（Survey）**：用于简化审计、调查或发现候选项。全程只读，交付按优先级排列的证据。
- **变更（Change）**：仅当用户明确要求简化、删除、合并、重构或修改仓库文档时使用。在授权边界内证明每项删减并完成验证。

再确定覆盖范围：

- **聚焦（Focused）**：用户指定了子系统、符号、状态机、依赖或疑似重复点。先彻底覆盖该边界，再决定是否扩展。
- **全库（Broad）**：请求覆盖整个仓库或多个候选项。按职责分区，并说明每个范围内领域的结论。

删除可达能力、已支持接口、持久化表示或兼容路径属于产品决策。若用户尚未明确选择，先说明后果并取得方向。

## 建立契约地图

1. 阅读仓库指令、架构与决策记录、清单、测试说明及生成文件约定。
2. 检查版本控制状态并保留无关改动；先识别供应商代码、生成物、迁移、fixture 和公开包边界。
3. 从入口沿配置、注册、分发、持久化、进程与网络边界追踪运行时路径；记录公开、动态、持久化、生成和兼容性敏感的契约。
4. 变更模式中，找出真实验证命令；可行时记录基线，基线失败会限制最终检查的证明力。

不得把授权、信任边界校验、安全隔离、无障碍要素、防数据丢失、存储格式兼容性和确保静默的清理逻辑当作附带的简化目标。除非用户明确授权并单独说明目标，否则应保留它们。

当范围内所有入口和权限边界都已列出、已追踪到能命名其所有者和可观察契约的深度，且未检查或无法得知的表面已作为盲区记录时，契约地图才完整。

## 覆盖相关表面

全库审计，以及涉及动态架构或依赖替换的聚焦任务，先阅读 [调查手册](references/investigation.md)，在排序发现前建立覆盖地图。不得因为发现第一个看似可删的点就停止。

若涉及并发、取消、就绪状态、清理、防御性复制、校验、授权、安全隔离、无障碍、防数据丢失或跨进程数据，同时阅读 [边界与生命周期](references/boundaries-and-lifecycle.md)。

将仓库原生搜索、编译器和静态检查输出、依赖元数据和历史记录视为线索，而不是删除证明。

## 为候选项建立证明记录

对每个已获得消费者地图证据或可能废弃重要契约的范围内线索，记录：

```text
候选项：待移除或合并的精确契约、表示或分层
负担：其带来的概念、同步、发布或测试成本
可达性：生产、非生产、动态、外部与持久化消费者
缘由：它为何存在，该理由是否仍然有效
删减边界：受影响的声明、实现、分支、产物、文档和依赖
后果：将放弃的可观察能力或兼容行为
置信度与风险：证据强度、不确定性、影响范围与可逆性
证明：能暴露错误删减的最小检查
净效应：移除的维护概念，减去新增的替代或迁移机制
```

候选项与幸存消费者共用文件时，必须把删减边界证明到文件以下的粒度；核对候选项独有的选择器、成员、字段、键、注册项、生成片段和 fixture，不能破坏存活所有者。

如存在真实消费者、动态可达性未解决、有效决策仍拥有该设计、复杂度只是被转移、结果超出范围或没有废弃重要义务、或无法用检查区分正确与偶然破坏，则保留或降低候选项等级。置信度与收益独立排序；高价值猜测不能超过小而已证实的删减。

## 决策和执行

审计模式在报告排序后的证据后停止；对有教育意义或暴露缺失事实的重要驳回项一并报告。

变更模式先阅读 [执行与恢复](references/execution-and-recovery.md)，选择最强且已授权的删减。默认每批只跨一个所有权边界；若用户明确授权多个删减，完成并验证当前边界后再处理下一项。

若用户要求简化方案、局部清理标记或设计记录整合，或选中的改动会使 ADR、RFC、设计说明或架构清单失效，阅读 [决策记录](references/decision-records.md)。不得把普通代码审计扩大成全仓文档清扫。

若用户要求整合其他分支、PR、任务或 Agent 的发现，阅读 [整合发现](references/integrating-findings.md)。保留证据，不保留候选项数量。

## 交付结果

审计应交付覆盖范围、排序后的证明记录、被驳回或未解决的高价值线索，以及解决每项不确定性所需的下一条事实。

变更应按 [执行与恢复](references/execution-and-recovery.md) 完成验证和操作回执。分层报告每项检查；局部测试通过不代表运行时、部署或用户验收已通过。
