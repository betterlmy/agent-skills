# 审计报告模板

```markdown
# 过度工程审计报告

## 摘要

- 仓库：
- 深度：quick / standard / deep
- 覆盖状态：完整 / 部分
- 已确认发现：
- 待验证候选：
- 预计净收益：
- 总体结论：
- 交付方式：回复内 / 绝对路径 / 未落盘

## 范围与方法

- 用户指定范围：
- 实际检查范围：
- 使用的检索与验证方式：
- 排除项及原因：
- 未检查区域：
- 覆盖受限原因：无 / 仓库规模 / 时间 / 权限 / 工具能力 / 其他

## 已确认发现

### P1. `标签` 简短结论

- 位置：`path:line`
- 证据：定义、消费者、配置、测试和契约的核验结果
- 当前成本：维护、依赖、认知或变更成本
- 建议：删除、内联、合并或替换方式
- 行为保持：为何替代方案保持当前必要行为
- 预计收益：代码与依赖区间，或定性收益
- 置信度：高 / 中
- 风险：高 / 中 / 低
- 验证：需要运行的测试、构建或人工验收

## 待验证候选

### C1. `标签` 候选结论

- 位置：`path:line`
- 已有迹象：
- 缺失证据：
- 确认方式：

## 多仓共同模式（仅多仓审计时输出）

- 模式：
- 涉及仓库：
- 可共享的治理建议：
- 不应合并的部署或契约边界：

## 估算口径

- 可删除或替换代码：约 N-M 行 / 无法可靠量化，改用定性收益
- 可移除直接依赖：N 个 / 无法可靠确认
- 不计入：生成物、测试调整、迁移代码等

## 未验证项与剩余风险

- 未验证项：
- 剩余风险：
- 临时文件清理风险：仅在报告写入临时目录时填写
```

没有正式发现时仍需报告实际覆盖范围，并直接说明“在已检查范围内未发现收益足以覆盖风险的精简项”，不要为了填充报告而输出低质量建议。
