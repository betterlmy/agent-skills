# 过度工程审计标准

## 结论门槛

正式发现需要同时满足：

1. 当前复杂度可以从源码、配置或依赖关系中定位。
2. 存在更简单且能保持已知行为、边界与质量属性的替代方案。
3. 已按声明的审计深度检查可见调用方、测试、注册机制和适用契约，并明确证据边界。
4. 精简收益足以覆盖迁移成本与回归风险。

任一条件证据不足且缺失信息可能推翻建议时，降级为待验证候选并写明需要补充的证据。缺失信息不影响建议本身、但影响适用范围或风险判断时，可以保留中置信度正式发现，但必须写明限制，不得声称可以无条件安全删除。

## 深度与证据门槛

- `quick`：以候选发现为主。只有局部证据闭合，且该结论不依赖未检查区域时，才允许形成正式发现。
- `standard`：必须闭合仓库内定义、消费者、入口、配置、测试和已知契约。仓库外消费者或运行时状态未知时，仅保留不受其影响的中置信度发现。
- `deep`：在 `standard` 基础上主动核验仓库外契约、动态注册、跨模块影响和主要失败路径；仍无法排除的关键隐式用途必须降级为候选。

深度决定主动核验范围，不降低共同底线：正式发现必须存在行为保持方案，且不得用文本搜索无结果证明绝对无用。

## 标签判定

### `delete`

适用于无有效消费者的实现、不可达分支、无人设置的配置、永久关闭的功能开关或没有需求依据的预留能力。

必须检查：动态调用、反射、模板引用、序列化字段、命令注册、路由注册、构建条件、迁移兼容和仓库外消费者。

### `yagni`

适用于只为假设性变化服务的接口、工厂、策略、分层或通用配置。

以下情况通常不成立：测试替身确有价值、抽象构成稳定边界、存在明确近期消费者、用于隔离第三方不稳定契约，或由架构规则强制要求。

### `delegate`

适用于只做一对一透传的包装层。若包装层承担鉴权、事务、重试、指标、协议转换、资源生命周期或稳定兼容边界，则不是纯透传。

### `duplicate`

适用于同仓库已有满足相同语义的实现。名称或代码形似不是重复证据；必须比较输入输出、失败语义、状态、副作用和并发约束。

### `stdlib` 与 `native`

替代能力必须满足当前支持版本、错误语义、安全属性、无障碍、国际化、性能约束和部署环境。不能只因 API 更短就建议替换。

### `shrink`

适用于保持可读性与行为时能明显简化的局部实现。代码高尔夫、压缩命名、吞异常、删除有效断言或把复杂度转移到隐式行为不算精简。

## 证据强度

- 高：声明范围内的定义、所有可见消费者、测试、适用契约和隐式注册路径均已核验，替代方案可直接说明，未检查区域不会推翻结论。
- 中：仓库内证据已闭合，仓库外消费者或运行时配置仍需确认，但这些未知信息不会推翻建议，只会限制适用范围或提高风险。
- 低：主要来自文本模式或局部源码，只能进入待验证候选。

## 风险与优先级

风险考虑公开契约、数据兼容、状态迁移、失败路径、部署耦合和回滚难度。优先级综合：

```text
净收益 = 维护成本下降 + 依赖减少 + 认知负担下降 - 迁移成本 - 回归风险
```

不要求虚构精确分数。证据不能支持数字时使用高、中、低，并解释依据。

## 常见误报

- 将面向仓库外部消费者的公开接口当成无调用代码。
- 忽略依赖注入、反射、插件、路由或序列化注册。
- 将测试夹具和故障注入点误判为无用抽象。
- 将安全、事务、幂等、重试和可观测性边界误判为包装层。
- 将跨仓协议的独立实现误判为可直接合并的重复代码。
- 用删除行数替代业务收益与风险判断。
