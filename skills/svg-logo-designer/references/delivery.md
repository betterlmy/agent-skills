# 交付与验收

## 分阶段交付

默认流程：

1. 概念阶段：2–3 个不同方向及简短理由，可以只提供主版草稿。
2. 选择阶段：用户选定一个方向并给出针对性反馈。
3. 完成阶段：只为选定方向制作必要版式和颜色版本。

用户明确要求一次性交付时，可以直接完成最合适的方向，但仍需记录假设和取舍。

## 推荐文件集合

按实际场景裁剪，不默认全部生成：

```text
brand-logo/
  acme-primary-horizontal-color.svg
  acme-primary-stacked-color.svg
  acme-mark-square-color.svg
  acme-primary-horizontal-mono-dark.svg
  acme-primary-horizontal-mono-light.svg
  usage.md
```

文件名使用小写连字符，不加入 `final-final`、日期或无意义编号。概念未批准前可以使用 `concept-a`，批准后改成用途名称。

## 每个文件的验收

- 品牌名、大小写和标语与简报完全一致。
- 存在 SVG 命名空间、`viewBox`、`title` 和 `desc`。
- 静态验证器通过。
- 没有脚本、事件、外部资源、DTD、实体、重复 ID 或悬空引用。
- 浅色、深色和透明背景下没有意外消失或低可见元素。
- 16、24、32 px 等关键小尺寸下轮廓仍可辨认；最小可用尺寸来自测试结果。
- 单色版本不依赖颜色差异表达关键结构。
- 画布没有意外裁切或过量空白，视觉重心合理。
- 最终字标已转路径，或文档明确记录字体与替换风险。

## 使用说明

`usage.md` 至少记录：

- 主版本和各变体用途。
- sRGB 十六进制颜色；需要印刷时说明必须校样。
- 建议安全空间及其测量基准。
- 经视觉测试得到的最小尺寸，而不是固定行业数字。
- 字体名称、字重、许可来源或已转路径状态。
- 禁止拉伸、旋转、任意改色、添加效果或改变组件关系。
- 静态验证和视觉检查的实际结果。
- 尚未执行的商标检索、字体许可确认或位图导出。

## 位图导出

只有用户需要且当前环境具备可验证的 SVG 渲染能力时才导出 PNG。先探测程序是否存在、查看其版本和帮助信息，再用临时样本确认透明背景与尺寸参数有效。

不要在 Skill 中假设某个外部程序或旧参数必然可用。若无法导出：

- 交付已验证 SVG。
- 清楚标记 PNG 未生成。
- 给出目标像素尺寸和背景要求，供用户在其设计工具中导出。

## 最终回复模板

```markdown
已交付：主横版、纯图形版、深色单色版。

设计：用两条互锁路径表达协作，保留清晰的单色轮廓。
颜色：#123456、#ABCDEF（sRGB）。
字体：字标已转路径；可编辑源稿使用 Example Sans Semibold。
验证：全部 SVG 静态验证通过；已检查浅/深背景和 24 px 显示。
未验证：未执行指定司法辖区的商标检索；未导出印刷 CMYK 文件。
```
