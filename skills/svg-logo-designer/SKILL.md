# SVG Logo Designer

把品牌需求转化为少量有区分度的概念，再将选定方向制作成结构清晰、可验证的 SVG。优先交付质量与可复用性，不默认批量生成几十个变体。

## 开始前

1. 读取 [设计工作流](references/design-workflow.md)。
2. 生成 SVG 前读取 [SVG 安全与技术规范](references/svg-safety.md)。
3. 准备最终文件时读取 [交付与验收](references/delivery.md)。
4. 修改触发描述或任务边界时，用 [触发评测用例](evals/trigger-cases.md) 回归检查。
5. 若用户提供现有品牌规范、草图或 SVG，先检查并以其为约束；不要擅自替换已批准的颜色、字形或构图。

## 判断任务边界

使用本 Skill：

- 从品牌简报创建原创 Logo 概念。
- 设计或迭代字标、字母标、图形标、抽象标或组合标。
- 为选定 Logo 制作横版、竖版、纯图形或单色版本。
- 生成可直接保存和验证的 SVG Logo。

不要使用本 Skill：

- 普通界面图标、插画、海报、图表或网页组件。
- 仅把已有 SVG 转成 PNG/PDF，且不涉及 Logo 设计。
- 商标检索、法律清查或完整品牌战略；可协助准备材料，但不得声称已完成法律审查。
- 临摹现有品牌，或“做成某品牌一模一样”。提取抽象特征后提出原创方向。

## 核心流程

### 1. 建立最小简报

从用户输入提取：品牌名、业务、受众、品牌气质、使用场景、必须包含/避免的元素、颜色偏好和文字准确性。

仅在缺失信息会改变设计方向时追问。每轮优先问一个、最多三个问题；若用户授权自主决定，则记录合理假设并继续。默认值：

- 先探索 2–3 个概念，不直接扩展全部版式。
- 同时考虑浅色、深色和单色环境。
- 优先简洁几何结构，确保小尺寸仍可辨认。

### 2. 提出概念

每个概念给出简短名称、核心隐喻、构图、色彩策略和适用场景。概念之间必须在形态或策略上有真实差异，不能只是换颜色。

不要宣称“独一无二”“无商标风险”或“符合所有文化”。未做外部检索时，把原创性判断限定为当前创作过程；用户需要商用清查时，建议进行专业商标检索。

### 3. 制作 SVG

- 使用明确的 `viewBox`，围绕真实图形边界构图。
- 使用路径和基础图形；草稿可用 `<text>`，最终字标应优先转为路径，或明确记录字体、回退和许可风险。
- 为每份文件提供唯一且有意义的 `<title>`、`<desc>`。
- 对品牌名等用户文本进行 XML 转义。
- 不使用脚本、事件属性、外部资源、远程字体、`foreignObject`、DTD 或实体。
- ID 在单文件内必须唯一；所有 `url(#id)` 与本地 `href` 必须能解析。

### 4. 验证与视觉检查

对每个 SVG 运行：

```bash
python3 scripts/validate_svg.py path/to/logo.svg
```

验证通过后，再用当前环境可用的预览能力检查：裁切、留白、对齐、线宽、文字溢出、浅/深背景、16–32 px 小尺寸和单色可辨认性。静态验证不能替代视觉检查；无法渲染时明确报告“结构已验证，视觉未验证”。

验证器的回归测试位于 `tests/test_validate_svg.py`。

### 5. 迭代与交付

先让用户选择方向，再制作必要版式和颜色版本。若用户明确要求一次性交付，则选择最符合简报的方向完成，并说明取舍。

文件名使用小写连字符，例如：

```text
acme-primary-horizontal-color.svg
acme-mark-square-mono-dark.svg
```

最终回复说明：设计理由、交付文件、颜色值、字体或路径状态、验证结果、视觉检查状态，以及任何商标、字体许可或导出限制。

## 失败与降级

- 简报矛盾：指出冲突及其对可读性或品牌表达的影响，再请求一个关键决策。
- 用户文字导致 XML 失败：修正转义，不删除或改写品牌名。
- 验证器报错：修复根因后重跑；不得绕过验证或放宽安全规则来交付。
- 无法导出位图：仍交付已验证 SVG，说明未执行位图导出；不要假设某个外部程序已安装。
- 无法完成视觉预览：交付前明确列为未验证事项。
